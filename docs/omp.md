# OMP (Oh My Pi) против pi и против «Волны»

Разбор по просьбе: что это за продукт, чем отличается от pi, чем отличается от «Волны», что выбрать и
что стоит перенять. Данные на сентябрь 2026, источники в конце. Всё, что не проверено в этом репозитории
руками, помечено как непроверенное.

## Что это

OMP - форк pi, сделанный Can Bölük 31 декабря 2025 года: «coding agent with the IDE wired in». Тот же
минимальный скелет pi, на который навешано всё остальное. Ставится своим бинарником (`omp`), живёт в
`~/.omp/`, публикуется своими пакетами (`@oh-my-pi/pi-coding-agent`), то есть это **не плагин к pi и не
надстройка над ним**, а отдельный агент общего с pi происхождения.

Устройство: TypeScript снаружи, ~80 000 строк Rust внутри (шесть крейтов плюс N-API-адаптер). В Rust
ушло то, за что обычно платят подпроцессами: поиск, оболочка с 46 встроенными coreutils, разбор AST через
tree-sitter (50+ языков), обход дерева файлов, изоляция рабочих копий, PTY, подсчёт токенов. Заявленный
принцип - «никаких подпроцессов на горячем пути».

## Чем отличается от pi

| | pi | OMP |
|---|---|---|
| Системный промпт | ~1000 токенов | «batteries included», больше |
| Инструменты | 4 (`read`, `write`, `edit`, `bash`) + то, что дописал сам | 31+ встроенных |
| Поиск, оболочка | подпроцессы `fd`, `rg`, git-bash | в процессе, на Rust |
| Правки | обычный текстовый `edit` | hashline: якоря по хэшу содержимого |
| Модели | 20+ провайдеров | 40+ провайдеров, роли моделей (`default`, `smol`, `slow`, `plan`, `commit`, `vision`, `task`, `advisor`, `tiny`) |
| Код-интеллект | нет | LSP (диагностика, переходы, переименования) и DAP (точки останова, шаги, стек) |
| Подагенты | своими руками | инструмент `task`: параллельные воркеры в изолированных worktree, результат по схеме |
| Наблюдение за подагентами | нет | Agent Hub (Alt+A): роспись воркеров, живые расшифровки, сообщения, убийство зависших |
| Память | нет | `retain`, `recall`, `reflect`, `memory_edit`, `learn`, `manage_skill` |
| Контекст | `/compact` | `checkpoint` + `rewind`: свернуть разведку, оставив отчёты |
| Прочее | - | браузер, управление рабочим столом, web_search по 23 провайдерам, github, генерация картинок, TTS, security_scan |

Что из этого стоит знать до восторгов - замеры Composio (DeepSeek V4 Flash, 30 задач): pi 558 885 токенов
на задачу, $0,028 за успех, 132 с медиана, 20/30 решено; OMP 742 283 токена, $0,103, 272 с, 17/30. То есть
OMP на тех же задачах **дороже на треть по токенам и вдвое медленнее**, и при этом решил меньше. Автор
разбора называет причину прямо: «OMP часто делает больше работы, чем нужно». Выигрыш у OMP там, где
инструменты действительно нужны: многоформатные файлы (PDF, SQLite, ноутбуки, архивы), слабые и дешёвые
модели (hashline поднял одну модель с 6,7% до 68,3% успешных правок), отладчик и LSP.

Оба форка делят TypeScript-API расширений и ветвящиеся сессии, оба подхватывают чужие конфиги
(`.claude`, `.cursor`, `.codex`, `.gemini`) при первом запуске. Windows у OMP свой бинарник без WSL.

## Чем отличается от «Волны»

Главное: **это разные категории, а не конкуренты**. OMP - харнес: процесс, TUI, инструменты, провайдеры,
подагенты. «Волна» - дисциплина ведения одной задачи внутри харнеса: этапы, журнал работ, адвокат
дьявола, вика выводов, гейты. OMP не ведёт задачу и не пишет журнал; «Волна» не рисует TUI и не держит
провайдеров моделей.

Пересечения всё же есть, и там видно разницу подходов:

| Тема | OMP | «Волна» |
|---|---|---|
| Подагенты | `task`: параллельно, в изолированных worktree, результат по схеме | по одной части, последовательно: журнал один, `state.json` указывает на одну задачу, параллельные ветви дают гонку записи |
| Ревью | `/review`: подагенты-ревьюеры, приоритеты P0-P3 | этап `advocate`: отдельный процесс только на чтение, база - точка начала части, вердикт из трёх слов, порции с журналом проверенного |
| Второе мнение | роль `advisor`: вторая модель комментирует каждый ход | адвокат вызывается этапом, а не висит на каждом ходе |
| Память | банк памяти с `retain`/`recall`/`reflect` | журнал задачи на диске плюс вика выводов в репозитории; коммитится вместе с работой |
| Свёртка контекста | `checkpoint`/`rewind` внутри сессии | чек-пойнт в журнал, отмена сжатия при отставшем журнале |
| Постановка | `todo` со фазами | этапы `spec`/`plan` с критериями приёмки в журнале |

«Волна» сознательно дешевле по префиксу (спит в проектах без `.volna`, скиллы не в манифесте) и упирает
на восстановимость: журнал пишется так, чтобы задачу можно было поднять с нуля. OMP упирает на мощность
инструментов в моменте.

## Что использовать

- **Останавливаться на pi + «Волна»** - для этого репозитория и вообще для работы, где ценятся дешёвый
  ход и предсказуемость. «Волна» написана под API pi, тесты гоняют её ядро напрямую, доставка и адвокат
  проверены на Windows. Менять харнес под задачи, которые и так решаются, - смена фундамента ради
  инструментов, которыми мы пока не пользуемся.
- **Смотреть в сторону OMP** - когда появится работа, где его инструменты незаменимы: отладка по DAP
  (segfault в C, зависший goroutine), массовые переименования через LSP, чтение PDF/SQLite/ноутбуков как
  файлов, работа слабой локальной моделью (там hashline даёт не проценты, а разы).
- **Не мигрировать «Волну» на OMP наугад.** API расширений у форков общий, но совпадение не проверялось,
  а «Волна» зависит от API pi в трёх местах (`tools.ts`, `commands.ts`, `index.ts`) и, что важнее, поднимает
  подпроцессы `pi` с конкретными флагами (`--mode json -p --no-session --no-extensions --no-skills
  --no-prompt-templates --tools ... --append-system-prompt`). Под OMP это отдельный бинарник со своим
  набором флагов и своим способом найти себя (`piagent.ts:piInvocation` ищет `pi`/`cli.js`). Проверять
  это надо прогоном, а не чтением README.

## Что стоит перенять

По убыванию отношения пользы к работе.

1. **Отчёт подагента по схеме, а не прозой.** У OMP `task` возвращает объект, проверенный схемой; у нас
   подагент отвечает пятью полями текстом, и оркестратор разбирает их регуляркой (`runner.ts:parseOutcome`).
   Пять полей уже есть - осталось проверять их наличие кодом и требовать добор, а не «спроси отчёт в своей
   сводке». Это прямо про нашу боль: отчёт без свидетельств выглядит как сделанная работа.
2. **Приоритеты находок адвоката (P0-P3 у `/review`).** Сейчас вердикт трёхзначный, а находки внутри
   отчёта равноправны, и решение «чинить сейчас или записать» принимает модель по наитию. Ранг находки -
   это поле, его можно требовать форматом и по нему решать, открывать ли итерацию `implement`.
3. **`rewind` как идея: свернуть разведку, оставив вывод.** У нас чек-пойнт пишет журнал, но контекст
   разведки остаётся в окне до `/compact`. Свёртка «прочитал двадцать файлов - оставил абзац» - то, ради
   чего подагент и заводится; из этого мог бы вырасти этап или инструмент «разведка подагентом».
4. **Роли моделей под задачу.** У нас две строки профиля (`модель адвоката`, `модель подагента`), у OMP -
   девять ролей с переключением на ходу. Третья-четвёртая строка профиля (модель плана, модель дешёвой
   разведки) стоит дёшево и бьёт по цене хода прямо.
5. **Наблюдаемость подагента.** Agent Hub показывает живую расшифровку и даёт вмешаться. У нас есть
   `onProgress` с числом вызовов и хвостом текста - на футер этого хватает, но зависший прогон видно только
   по таймауту. Полезным был бы хотя бы файл живого лога подпроцесса рядом с диффом: после таймаута сейчас
   остаётся частичный вывод в ответе и больше ничего.
6. **Изоляция рабочей копии для подагента (`pi-iso`, worktree на воркер).** Нам это нужно не для
   параллельности (её мы отвергли осознанно: журнал один), а для страховки: подагент с правами на запись
   сейчас держится промптом «не коммить». git worktree на прогон части сделал бы запрет устройством.
7. **Hashline-правки** - не переносится, это уровень харнеса, а не пакета. Но знать стоит: если в проекте
   работают слабой моделью и правки ломаются, дело может быть в формате правок, а не в модели.

Чего перенимать не стоит: 31 инструмент в системном промпте, вторую модель на каждом ходе, магические
слова в прозе (`ultrathink`, `orchestrate`, `workflowz`). Для «Волны» это ровно то, от чего она уходит:
префикс платится каждым запросом, а флоу держится на инструментах, а не на словах в тексте.
