# Проект: <название>

Файл читают этапы «Волны». Правило одно: **чего в профиле нет, того этап не делает**.

## Профиль

Строка со значением в угловых скобках означает «человека ещё не спросили»: этап, которому она
нужна, остановится и спросит. Ненужную строку можно удалить - это и будет «предмета нет».

- тесты: <команда запуска тестов | нет>
- сборка: <команда сборки | нет>
- запуск: <команда запуска приложения | нет>
- визуальная проверка: <chrome-devtools | нет>
- скриншот модели: нет
- endpoint браузера: 
- эталон: <путь к эталонной реализации | нет>
- модель адвоката: наследовать
- расширения адвоката: нет
- гейт правок: да
- доставка: <нет | commit | commit+push>
- ветка: <тип>/<задача>
- база: 
- удалённый: origin
- изменения: 
- дифф: 
- не смотреть: 
- трекер: нет
- вики: нет
- kb: нет

Пояснения к строкам, которые не говорят сами за себя:

- **визуальная проверка** - `chrome-devtools` означает проверку в браузере, которым управляет
  расширение `pi-chrome-devtools` (`pi install npm:@narumitw/pi-chrome-devtools`). Своего браузера
  «Волна» не поднимает: два движка в одном проекте дают две разные картинки и спор о том, какая
  правда.
- **скриншот модели** - отдавать ли картинку модели вместе с отчётом визуальной проверки. `да`
  имеет смысл только для модели, которая видит изображения; путь к файлу возвращается всегда.
- **endpoint браузера** - пусто означает «как настроено в pi-chrome-devtools» (по умолчанию
  `http://127.0.0.1:9222`). Заполняется только там, где браузер слушает другой порт.
- **модель адвоката** - `наследовать` означает модель по умолчанию pi. Можно указать id модели:
  адвокат идёт отдельным процессом, и ему не обязательно быть той же модели, что основная сессия.
- **расширения адвоката** - адвокат идёт отдельным процессом pi с отключёнными расширениями.
  `да` нужно там, где провайдер модели регистрируется расширением pi: иначе подпроцессу не из чего
  выбирать модель, и он вернётся пустым.
- **доставка** - что делает этап `deliver`: `нет` (доставку делает человек сам, этапа в проекте не
  существует), `commit` (коммит в ветку задачи) или `commit+push` (ещё и отправка). Доставка работает
  только в git: другие системы контроля версий «Волна» читает, но не пишет.
- **ветка** - шаблон имени ветки задачи: `<тип>` (bugfix, feature, research по типу задачи),
  `<задача>` (идентификатор), `<слаг>` (идентификатор без даты). `нет` означает работу в текущей
  ветке. Ветка одна на задачу: части ложатся в неё подряд.
- **база** - от чего ответвляться (`main`, `develop`). Пусто означает «от текущей ветки».
- **удалённый** - имя удалённого репозитория для push. Пусто означает `origin`.
- **изменения** и **дифф** - команды, печатающие изменённые файлы и дифф, если система контроля
  версий в проекте не git, не svn и не hg. Через них подключаются TFVC (`tf vc status . /recursive`),
  Perforce (`p4 opened`) и самописные скрипты. Пусто означает «определить самому»: git, svn, hg или,
  если ничего из них нет, снимок дерева, который «Волна» снимает перед первой итерацией реализации.
- **не смотреть** - каталоги и файлы, которые снимок дерева пропускает, через запятую. Обычные
  подозреваемые (`node_modules`, `dist`, `bin`, `obj`, `.vs`) пропускаются и без этой строки.
- **гейт правок** - `да` не даёт править код на этапах разбора, постановки и плана. Снимается
  строкой `нет`, если такой порядок мешает.
- **трекер**, **вики**, **kb** - оставлены на будущее. Сейчас значение `нет` и работают только
  локальные журналы.
