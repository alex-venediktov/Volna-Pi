# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Пакет для [pi](https://pi.dev): расширение `extensions/volna` плюс скиллы `skills/`. Ведёт одну задачу по
флоу этапов с журналом работ, адвокатом дьявола в отдельном процессе `pi` и визуальной проверкой через
CDP. Сборки нет — pi грузит TypeScript через jiti.

## Команды

```bash
npm install                       # typescript, типы node и peer-пакеты pi
npm run check                     # tsc --noEmit, единственный линт в проекте
npm test                          # node --experimental-strip-types tests/all.ts
pi -e .                           # запустить pi с этим пакетом без установки
```

Один набор тестов вместо всех:

```bash
node --experimental-strip-types --input-type=module \
  -e "import {run} from './tests/parts.test.ts'; import {results} from './tests/harness.ts'; await run(); console.log(results());"
```

Живая проверка загрузки расширения:

```bash
printf '{"id":"1","type":"get_commands"}\n' | pi --mode rpc --no-session -e .
```

Она падает с `Tool "volna_init" conflicts`, если тот же пакет **установлен** в pi (`pi install`): две копии
регистрируют одни имена. Это не дефект правки — снять установленную копию или проверять тестами.

## Правила, которые видно только по нескольким файлам

**Язык разный по адресату.** Всё, что уходит модели — описания инструментов, блок обязанностей
(`stages.ts:stageDuties`), инструкции этапов `skills/volna-flow/stages/*.md`, промпт адвоката — **по-английски
и сжато**: пакет рассчитан на локальные модели, где префикс платится на каждом запросе. Русский там, где
читают люди: журнал, сообщения команд, футер, профиль проекта, README, комментарии в коде.

**Флоу держится на инструментах, а не на просьбах в промпте.** Этап, номер итерации, метку времени и формат
секции ставит код (`core.ts`, `journal.ts`). Модель решает, что написать, а не как это оформить и когда
пометить этап пройденным.

**Зависимость от API pi только в трёх файлах**: `tools.ts`, `commands.ts`, `index.ts`. Остальное ядро —
обычный node, поэтому тесты гоняют его напрямую без моков pi. Новый код по возможности класть в ядро.

**Имя этапа одно в четырёх местах**: `STAGES` в `stages.ts`, файл `skills/volna-flow/stages/<имя>.md`,
значение `stage` во frontmatter журнала, хвост имени команды `/volna:<имя>`. Расхождение значит, что что-то
одно неверно.

**Команда и инструмент идут одной дорогой.** `/volna:analyze` и `volna_stage` вызывают одну функцию ядра —
расхождение «человек нажал» против «модель решила» было бы источником самых непонятных ошибок.

## Раскладка

| Модуль | О чём |
|---|---|
| `core.ts` | приём задания, вход в этап, пропуск, закрытие части и задачи, шапка, сводка |
| `journal.ts` | два файла журнала: frontmatter + «Состояние» и append-only лог итераций |
| `parts.ts` | задача из нескольких частей: список в «Состоянии», `part`/`parts` во frontmatter |
| `assignment.ts` | задание текстом или ссылкой на файл (путь, `@`, `file://`, `~`) |
| `state.ts`, `frontmatter.ts`, `paths.ts` | state.json, свой минимальный YAML, раскладка `.volna` |
| `changes.ts`, `diff.ts` | откуда брать правки для адвоката, свой unified diff |
| `git.ts` | доставка: ветка задачи, коммит части, push (единственное, что «Волна» пишет в VCS) |
| `advocate.ts` | подпроцесс `pi` с чистым контекстом и правами только на чтение |
| `visual.ts`, `cdp.ts` | браузер pi-chrome-devtools по Chrome DevTools Protocol |
| `index.ts` | события pi: шапка, гейт правок, отмена сжатия, футер |

## Инварианты журнала

`.volna/journal/TASK-<id>.md` — frontmatter и переписываемая секция «Состояние», по ней задача
восстанавливается с нуля. `logs/TASK-<id>.log.md` — append-only, прошлые секции не переписываются никогда.
При противоречии слоёв прав файл состояния.

- **Имена подпунктов «Состояния» фиксированы** (`STATE_LABELS`): подпункт с другим именем никто не найдёт —
  ни `journalIssues`, ни шапка, ни следующая сессия.
- **`state_sync`** хранит последнюю секцию лога на момент перезаписи «Состояния». Отставание по меткам
  времени не поймать: формат меток до минут, запись и перезапись попадают в одну минуту.
- **Список частей переносится сам**, когда `action=state` вызвали без него: он источник правды об остатке, и
  забытое поле стёрло бы остаток задачи.
- Метки времени берутся у часов машины: по ним на закрытии считаются часы.

## Границы версии

Доставка есть только в git и только по профилю (`доставка`, `ветка`, `база`, `удалённый`): `нет` означает,
что этапа `deliver` в проекте не существует. Этап стоит перед `close`, то есть внутри цикла части: одна
ветка на задачу, коммит (и не один, если часть того требует) на каждую часть. Push спрашивает согласие
человека и не делается без него; force push не делается никогда. Читать «Волна» умеет и svn, hg, TFVC и
снимок дерева, писать — только в git. Трекера, PR, вики и базы знаний нет: профиль эти строки описывает,
этапы про них знают, кода под них нет.

## Тесты

`tests/harness.ts`: `check(label, condition, extra)`, `sandbox(name, {git})`, `exec` с контрактом `pi.exec`,
`toolText`. Новый набор — файл `tests/<тема>.test.ts` с `export async function run()` плюс строка в
`tests/all.ts`. Метки проверок по-русски, утверждением о поведении.

Модели тесты не касаются: проверяется то, что должно работать одинаково при любой модели. Инструменты
тестируются через `registerTools` с поддельным `pi`, события — через вызов `volna(fakePi)`.

## Профиль проекта

`.volna/project.md`, секция `## Профиль`. Правило: **чего в профиле нет, того этап не делает** — молча, без
записи «пропущено». Значение в угловых скобках (`<chrome-devtools|нет>`) значит «не спрошено»: этап
останавливается и спрашивает, а не догадывается (`state.ts:isPlaceholder`).
