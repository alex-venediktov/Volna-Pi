# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Пакет для [pi](https://pi.dev): расширение `extensions/volna` плюс скиллы `skills/`. Ведёт одну задачу по
флоу этапов с журналом работ, адвокатом дьявола в отдельном процессе `pi`, визуальной проверкой через
CDP, викой выводов и прогоном частей подагентами. Сборки нет — pi грузит TypeScript через jiti.

## Команды

```bash
npm install                       # typescript, типы node и peer-пакеты pi
npm run check                     # tsc --noEmit, единственный линт в проекте
npm test                          # node --experimental-strip-types tests/all.ts
pi -e .                           # запустить pi с этим пакетом без установки
```

Один набор тестов вместо всех:

```bash
node --experimental-strip-types --input-type=module \
  -e "import {run} from './tests/parts.test.ts'; import {results} from './tests/harness.ts'; await run(); console.log(results());"
```

Живая проверка загрузки расширения:

```bash
printf '{"id":"1","type":"get_commands"}\n' | pi --mode rpc --no-session -e .
```

В каталоге самого пакета `.volna` нет, поэтому в списке будут только `/volna:init` и `/volna:doctor` — остальное
поднимается лишь там, где «Волна» развёрнута. Полный набор проверяется тем же вызовом из каталога с `.volna`.

Если тот же пакет ещё и **установлен** в pi (`pi install`), в развёрнутом проекте работают две копии: команды
приходят парами (`volna:task:1`, `volna:task:2`), а на одинаковых именах инструментов может выйти
`Tool "volna_init" conflicts`. Это не дефект правки — снять установленную копию или проверять тестами.

## Правила, которые видно только по нескольким файлам

**Пакет спит там, где «Волна» не развёрнута.** Инструменты, команды этапов и скиллы регистрируются только
при найденной `.volna` (`index.ts:waker` и обработчик `resources_discover`), а `registerSetupCommands` держит вне
её `/volna:init` и `/volna:doctor`. Скиллы поэтому и убраны из `pi.skills` в `package.json`: манифест грузил бы их
описания в системный промпт любого проекта. Установленный глобально пакет иначе платил бы префиксом на каждом
запросе там, где задачу никто не ведёт.

**Язык разный по адресату.** Всё, что уходит модели — описания инструментов, блок обязанностей
(`stages.ts:stageDuties`), инструкции этапов `skills/volna-flow/stages/*.md`, промпт адвоката — **по-английски
и сжато**: пакет рассчитан на локальные модели, где префикс платится на каждом запросе. Русский там, где
читают люди: журнал, сообщения команд, футер, профиль проекта, README, комментарии в коде.

**Флоу держится на инструментах, а не на просьбах в промпте.** Этап, номер итерации, метку времени и формат
секции ставит код (`core.ts`, `journal.ts`). Модель решает, что написать, а не как это оформить и когда
пометить этап пройденным.

**Согласие человека спрашивается ровно один раз - на push** (`tools.ts`, `ui.confirm` либо `confirmed`).
Остальные этапы идут одной цепочкой до закрытия части или задачи; уровень `required` означает «этап не
пропускается», а не «этап ждёт команды». Ход возвращается человеку на развилке, стоп-критерии, макете и
границе части, где `/new` и следующий `/volna:task` набирает он сам. Постановка, план, дифф, скриншот и
итог показываются по дороге, а не вместо шага: остановка на каждом этапе стоит хода и не покупает ничего -
тот же текст лежит в журнале, и возразить на него можно в конце.

**Зависимость от API pi только в трёх файлах**: `tools.ts`, `commands.ts`, `index.ts`. Остальное ядро —
обычный node, поэтому тесты гоняют его напрямую без моков pi. Новый код по возможности класть в ядро.

**Имя этапа одно в четырёх местах**: `STAGES` в `stages.ts`, файл `skills/volna-flow/stages/<имя>.md`,
значение `stage` во frontmatter журнала, хвост имени команды `/volna:<имя>`. Расхождение значит, что что-то
одно неверно.

**Команда и инструмент идут одной дорогой.** `/volna:analyze` и `volna_stage` вызывают одну функцию ядра —
расхождение «человек нажал» против «модель решила» было бы источником самых непонятных ошибок.

## Инварианты журнала

`.volna/journal/TASK-<id>.md` — frontmatter и переписываемая секция «Состояние», по ней задача
восстанавливается с нуля. `logs/TASK-<id>.log.md` — append-only, прошлые секции не переписываются никогда.
При противоречии слоёв прав файл состояния.

- **Имена подпунктов «Состояния» фиксированы** (`STATE_LABELS`): подпункт с другим именем никто не найдёт —
  ни `journalIssues`, ни шапка, ни следующая сессия.
- **`part_open`** хранит часть, в которую вошло продолжение, и по ней же закрывается часть. Поле
  `part` для этого не годится: оно производная от списка («первая начатая»), и когда начатых
  несколько - а так бывает у всякой части, отложенной до человека, - показывает не ту. Закрытие без
  этой записи гадает тем же способом и закрывает чужую часть под итогом этой.
- **`state_sync`** хранит последнюю секцию лога на момент перезаписи «Состояния». Отставание по меткам
  времени не поймать: формат меток до минут, запись и перезапись попадают в одну минуту.
- **Список частей переносится сам**, когда `action=state` вызвали без него: он источник правды об остатке, и
  забытое поле стёрло бы остаток задачи.
- Метки времени берутся у часов машины: по ним на закрытии считаются часы.

## Границы версии

Доставка есть только в git и только по профилю (`доставка`, `ветка`, `база`, `удалённый`): `нет` означает,
что этапа `deliver` в проекте не существует. Этап стоит перед `close`, то есть внутри цикла части: одна
ветка на задачу, коммит (и не один, если часть того требует) на каждую часть. Push спрашивает согласие
человека и не делается без него; force push не делается никогда. **Правки «Волна» читает только из git**:
своего трекинга изменений у неё нет, других систем контроля версий она не знает, и без git этап `advocate`
отказывается работать, а не проверяет проект целиком. Остальной флоу вне git идёт как обычно. Трекера и PR
нет: профиль эти строки описывает, этапы про них знают, кода под них нет.

**Граница поиска `.volna`** (`paths.ts:findVolnaDir`): подъём вверх останавливают каталог с `.git`
(чужой репозиторий), корень диска и домашний каталог. Вне git первых двух признаков мало: без границы
`~/.volna`, развёрнутая когда-то не там, становится настройкой для всего, что под ней. Параметр
`stopAbove` существует ради теста — в бою он всегда `homedir()`.

**`.gitignore` заводится только в git-репозитории.** Вне git `init` разворачивается, но говорит, чего в
проекте не будет (`InitResult.warnings`), и правил не пишет.

**Сплошное правило `.volna/` в `.gitignore` ломает вику молча** (`init.ts:blanketIgnoreRule`): записи
заводятся, линт чист, а в коммит не уходит ни профиль проекта, ни выводы, ради которых `capture` стоит
перед `deliver`. Точечными правилами это не чинится - git внутрь исключённого каталога не заходит, и
отменить исключение изнутри нечем. Поэтому `init` под таким правилом своих не дописывает (они были бы
мертвы, но выглядели бы сделанной работой), а говорит, чем строку заменить; доктор повторяет то же.
Чужое правило «Волна» не переписывает сама.

**Дифф адвокату не кладётся файлом** (`advocate.ts`): в задание идёт готовая команда
`git diff <база> -- <файлы порции>`, а новые файлы названы отдельно - их `git diff` не покажет, потому
что индекс «Волна» не трогает. Файл означал путь в промпте, который модель обязана воспроизвести:
путь через домашний каталог на Windows бывает кириллическим, и однажды прогон ушёл искать
`batch-1.diff` по всему диску - молча, без нагрузки, до таймаута. В `.volna/advocate/<задача>/`
остаются только журнал проверок и отчёты порций.

**Адвокат идёт порциями, и это про таймаут, а не про контекст** (`advocate-batches.ts`). Один вызов
`volna_advocate` разбирает несколько файлов диффа (бюджет в байтах, файл целиком), пишет вердикт и отчёт в
журнал проверок и помечает проверенные куски хэшем. Снятый прогон порцию не зачитывает -
её файлы приходят в следующий, а разобранное остаётся разобранным; один длинный прогон на весь дифф терял
всю работу проверки целиком. Правка меняет хэш куска, и файл возвращается в очередь сам; смена базы
сбрасывает журнал проверок.

**Подпроцесс снимается вместе с детьми** (`piagent.ts:killTree`): `taskkill /T` на Windows, группа
процессов на unix (для неё `spawn` идёт с `detached`). Сигнал одному `pi` оставляет жить оболочку и то, что
она запустила, - на Windows это `find.exe` из Git for Windows, по процессу на вызов, и осиротевшие копии
копятся от прогона к прогону. Поэтому же промпты адвоката и подагента требуют искать инструментами
`grep`/`find` самого pi (это `rg` и `fd`), а `bash` держать для команд проекта и чтения git.

**Журнал из диффа адвоката вычтен** (`changes.ts`, пути `:(exclude).volna/journal/`). Его пишет сам
флоу, и разбирать его - не разбор работы. Цена не в точности, а во времени: лог итераций растёт на
каждую часть и к середине задачи занимает целые порции, которые адвокат читает вместо кода (замер на
фазе 1: 419 строк диффа, из них 344 журнальных). Вика остаётся: её содержание - утверждения о
проекте, и проверить их стоит.

**База адвоката — точка начала части, а не `HEAD`.** SHA пишется во frontmatter (`part_base`) на первой
итерации `implement` и сбрасывается закрытием части. Иначе коммит внутри части (в том числе на `deliver`)
уводил бы проверенное из-под адвоката, а при `доставка: нет` дифф следующей части приходил бы вместе с
предыдущей.

## Инварианты вики

`.volna/wiki/` коммитится, в отличие от журнала: журнал - ход работы одного человека, вика - знание команды.
Запись заводит этап `capture`, и стоит он перед `deliver` ровно затем, чтобы запись уехала тем же коммитом,
что и работа.

- **Единица хранения - вывод, а не страница про сущность.** Заголовок это утверждение; поля `тип`,
  `предмет`, `этапы`, `вывод` обязательны, а имена полей русские: формат записи - данные, а не промпт.
- **Указатели собираются, а не пишутся** (`wiki-ops.ts`, действие `index`): ручная правка затирается, а
  мёртвые шарды сборка удаляет - указатель переименованного узла выглядит живым и отдаёт устаревший перечень.
- **Набор этапов вики берётся у флоу** (`wiki.ts`, `DEFAULTS.stages` = `STAGE_NAMES`): свой список
  разошёлся бы с `STAGES` и забраковал записи с законными этапами (`K008`).
- **Относительный корень сверки отсчитывается от корня проекта**, а не от каталога процесса
  (`wiki-ops.ts:projectRootOf`): pi запускают и из подкаталога, и тогда `root: "."` превратил бы живые
  якоря в «файла нет», а линт остался бы чистым.
- **Без `fix` ни одна операция в файлы не пишет.** Коды возврата те же, что у CLI плагина: 0 чисто,
  1 ошибки, 2 только предупреждения, 3 сбой.
- Из плагина не перенесены `flatten` и `migrate` (миграции истории, которой у pi-пакета не было) и
  разведочный `wiki-survey`.

## Подагенты

Подагент законен как чтение внутри этапа - сходить, прочитать много, вернуть короткий вывод. Ветвью флоу он
не становится, и упирается это не в цену, а в устройство: журнал один, `state.json` указывает на одну
активную задачу и по ней держит гейт правок, параллельные ветви дают гонку записи.

`/volna:parts-run` и `volna_part` гонят незакрытые части по одной. Подагент здесь **работник, а не вторая
ветка флоу**: расширения «Волны» ему выключены (`runner.ts`), поэтому инструментов этапа, журнала и гейта у
него нет вовсе - он делает работу одной части и отчитывается пятью полями, а этапы, адвокат, тесты и
закрытие части остаются на оркестраторе. Условия запуска проверяет код (`partsRunReadiness`): активная
задача, больше одной незакрытой части, не отставший журнал. Всё, кроме `ИТОГ: сделано`, прогон останавливает:
независимость частей - оценка, сделанная до работы.

**Постановка части лежит в логе, а не в списке частей** (`parts.ts:parsePartBriefs`): подпункт `части`
секции `spec`, блок на часть с полями `готово, когда`, `трогает`, `не трогает`, `зависит от`. Список в
«Состоянии» переписывается целиком на каждом закрытии - подробности в нём не выжили бы, а критерий нужен
именно тогда, когда часть уходит подагенту. `volna_part` берёт критерий оттуда и без него часть не отдаёт;
форма одна на промпт и на сообщение об ошибке (`partBriefForm`), иначе они разъедутся.

Права на запись у подагента настоящие, и запрет коммитить держится промптом, а не устройством: `bash` ему
нужен для проверок проекта.

## Внешний прогон

`tools/plan-run.ts` гонит незакрытые части полным флоу, каждую своей сессией `pi --mode rpc`. Это
не вторая ветка флоу и не подагент: **флоу ведёт сама сессия** (расширения «Волны» включены), а
драйвер снаружи подаёт часть, сторожит молчание и читает итог. Запускается обычным node - изнутри
pi он дал бы сессию внутри сессии с общим журналом и гонкой записи.

**Чистый контекст между частями даёт процесс, а не `new_session`.** Граница процесса заодно
переживает падение pi и не тащит дальше ни кэша, ни подвисших инструментов; `new_session` из
драйвера ещё и недоступен без команды - в pi он живёт на `ExtensionCommandContext`.

**Итог части берётся не из статуса, а из следа инструмента** (`autopilot.ts:partClosed`). Статус в
списке частей «Состояния» лежит на диске, но пишет его сама сессия (`volna_journal action=state`), и
слово «сделано» в нём стоит ровно столько же, сколько заявление в ответе. Закрытие оставляет след,
которого рукой не поставишь: секцию `close` с этой частью в append-only логе (`closeLogged`). Без
этого сессия, дошедшая до середины адвоката, помечает часть сделанной - и прогон идёт дальше, считая
её закрытой. «Снята» проверяется статусом: её ставит только полное закрытие задачи, на котором
прогон останавливается и так.

**Закрытию верят только про свою часть** (`autopilot.ts:strayChanges`). Доказать, что часть сделана,
в общем виде нельзя: у драйвера нет способа отличить работу от её описания. А вот поймать закрытие,
поставленное не туда, можно точно - список частей снимается до работы и после, и смена статуса у
любой части, кроме текущей, останавливает прогон. Сессии дали одну часть; правка чужого статуса
означает, что закрытие ушло не по адресу, а следующая часть уже пропущена как «закрытая». Сверка с
`трогает` из постановки была бы догадкой, а это - факт.

**В часть входит сама «Волна», а не просьба в промпте** (`autopilot.ts:enterPart`). Первым
заданием сессии идёт `/volna:task <номер>`: он поднимает задачу, ставит названную часть в работу и
вводит её в `spec` (`core.ts:resumeTask`) - то самое продолжение, которое «Волна» называет человеку
на закрытии части. Без него сессия открывается на этапе, которым кончилась предыдущая часть
(`close`), и флоу не начинается: модель читает журнал и ходит кругами.

**Номер части называется явно, потому что «очередная часть» у «Волны» своя.** Без аргумента
`resumeTask` берёт первую начатую, а у прогона она могла быть отложена ключом `--skip` как ждущая
человека. Тогда сессия получает шапку одной части и задание другой: работу она делает по заданию, а
журнал пишет под номером из шапки. Голый номер аргументом команды - номер части; всё прочее -
задание (`commands.ts`), потому что задания из одних цифр не бывает.

**Лог итераций дописывается инструментом и не читается ничем** (`index.ts`, `paths.ts:isJournalLog`,
`logReadInCommand`). Инструмент чтения на пути `.volna/journal/logs/*.log.md` получает отказ; из
оболочки закрыта любая команда, назвавшая этот путь. Исключение одно - `git add`, `git commit`,
`git rm`: им путь нужен, чтобы положить журнал в коммит, а не чтобы прочесть. Свой лог и чужой
закрыты одинаково: в чужом история задачи, к которой сессия отношения не имеет.

Послабление для адресного поиска стояло здесь раньше и себя не оправдало: сессия вытаскивала
`grep`-ом десятки строк за раз и набирала ту же историю чужих частей, просто порциями. Всё, что лог
имеет сказать, доходит до сессии через «Состояние» и через итоги закрытых частей.

Просьбой в промпте это не держится: просьбу видно один раз в начале хода, а тянется сессия к логу
тогда, когда уже потеряла нить, - и читает историю всех частей вместе с отвергнутыми подходами. В
чужом контексте брошенная гипотеза читается как факт о проекте.

**Лог итераций наружу не отдаётся никогда.** Ни сессии части, ни выводу по задаче: это история всех
итераций вместе с отвергнутыми подходами, и в чужом контексте брошенная гипотеза читается как факт.
Подпроцессу идёт «Состояние» плюс названные секции (`journal.ts:sectionsOf`) - адвокату критерии из
`spec` и `plan`, выводу по задаче итоги частей из `close`. Сессия части получает адрес «Состояния» и
прямой запрет ходить по логу поиском.

**Вывод по задаче - отдельная работа, а не хвост цикла** (`autopilot.ts:runTaskCapture`). `capture`
стоит внутри цикла части, и на сброшенном контексте видит только свою часть; сквозные выводы не
увидит никто. Поэтому на закрытой очереди прогон делает ещё одну сессию: она входит `/volna:capture`,
получает «Состояние» и итоги частей и пишет в вику то, чего не видно изнутри одной части. Задачу не
закрывает: `close` остаётся человеку.

**Граница части проверяется по файлам, а не по обещанию** (`autopilot.ts:strayFiles`). Поле
`трогает` постановки - это не догадка, там граница выписана явно. Драйвер снимает дерево git до
части и после и называет файлы, которых в границе нет; `.volna` не считается - журнал и вику правит
сам флоу. Пустое `трогает` проверять нечем, и тогда проверки нет вовсе.

**Закрытие по ручному критерию без единого вопроса - обход приёмки** (`autopilot.ts:needsHuman`).
Доказать делом машина не может, а поймать обход процедуры может: критерий со словами про человека,
глаз, телефон, устройство или замер, закрытый сессией, которая ни о чём не спросила, останавливает
прогон.

**Задачу закрывает человек, а не прогон.** Закрытие части - развилка, закрытие задачи - конец флоу:
активной задачи больше нет, гнать нечего, а остаток частей записан итогом, которого никто не
проверял. Драйвер сверяет активную задачу до части и после и останавливается, если она пропала.

**Часть отмечается взятой до показа хода** (`parts.ts:takePart`), как и у прогона подагентами: пока
сессия работает, карта частей и строка прогона обязаны говорить одно и то же, иначе остановка на
вопросе выглядит так, будто за часть никто не брался.

**Любой вопрос человеку останавливает прогон.** В режиме rpc `hasUI` истинно, и диалоги расширений
идут тем же потоком (`extension_ui_request`). Отвечает драйвер, и всегда отказом: неотвеченный
диалог держал бы сессию молча до сторожа, а положительный ответ выдал бы за данное согласие,
которого человек не давал. Поэтому push не случается ни при каком профиле.

**Круг одинаковых вызовов останавливает ход** (`autopilot.ts:REPEAT_LIMIT`, подпись вызова считается
в `rpc.ts`). Это не молчание и не перерасход: сессия говорит, события идут, счётчик вызовов растёт, а
работа стоит - поэтому не ловит ни сторож простоя, ни потолок вызовов. Замер на стенде сравнения:
пресет модели повторил одно чтение схемы вики 47 раз за 75 минут и до потолка так и не дошёл. Порог
низкий (пять подряд) намеренно: ошибочное прерывание стоит одного хода, незамеченный круг - часа.

**Сторож считает простой, а не длительность хода** (`rpc.ts`). Порогов два: `idleMs` на молчание
внутри начатого хода (прерывание `abort`, после оседания просьба продолжить - контекст хода цел) и
`startMs` на первый признак хода. Второй нужен потому, что не начавшаяся сессия молчит вечно, и
десятиминутное ожидание превращает «нет модели» в «узнаем через десять минут».

**Подставной собеседник живёт файлом** (`tests/rpc-stub.mjs`), а не строкой внутри теста: конечный
автомат хода - самое рискованное место драйвера, и проверять его на живом pi нельзя (нужна модель),
а генерировать текст программы escape-последовательностями внутри шаблонной строки - способ
получить синтаксическую ошибку вместо проверки.

## Сравнение моделей

`tools/bench-models.sh` гонит **одну и ту же часть от одного и того же коммита** каждой названной
моделью, каждую - в своём рабочем дереве git. Сравнивать модель A на части 2 с моделью B на части 3
нельзя: части разной трудности, и разброс между ними больше разброса между моделями. Дерево, а не
ветка в рабочем каталоге: прогон пишет журнал, вику и код, и ни одна из этих записей не должна
коснуться настоящей работы - от прогона нужны только числа.

`tools/bench-metrics.mjs` считает их по двум файлам, которые драйвер и так пишет: терминальному логу
и стенограмме. Своего учёта в драйвер ради сравнения не добавлено - измерение не должно менять то,
что измеряет.

**Скорость считается по стене, а не по времени генерации** (`plan-run.ts:spend`): простой между
ходами, чтение файлов и ожидание инструментов - такая же цена части. Число выходит меньше «токенов в
секунду» из бенчмарков движка и означает другое: сколько модель выдаёт на реальной работе. Кэш в
строке назван отдельно от свежего ввода - на длинной части он составляет почти весь ввод.

## Тесты

`tests/harness.ts`: `check(label, condition, extra)`, `sandbox(name, {git})`, `exec` с контрактом `pi.exec`,
`toolText`. Новый набор — файл `tests/<тема>.test.ts` с `export async function run()` плюс строка в
`tests/all.ts`. Метки проверок по-русски, утверждением о поведении.

Модели тесты не касаются: проверяется то, что должно работать одинаково при любой модели. Инструменты
тестируются через `registerTools` с поддельным `pi`, события — через вызов `volna(fakePi)`.

## Каналы зрения

**Визуальная проверка без картинки не считается сделанной** (`tools.ts`, инструмент `volna_visual`).
Каналов два, выбирает строка профиля `визуальная проверка`: `chrome-devtools` (браузер по CDP,
`visual.ts`) и команда проекта, печатающая путь к картинке последней строкой stdout (`shot.ts`).
Канала нет или он не спрошен - инструмент отказывается с объяснением, а не возвращает пустой отчёт.

Молчаливый пропуск здесь стоил дороже всего остального: сцена, в которой ни один узел не встал на
место, запускается и завершается ровно так же чисто, как рабочая. Пока канал был один и только
браузерный, в неверебном проекте этап `visual` не делал ничего ни разу, а «запустилось без ошибок»
оставалось единственным доступным утверждением - и уезжало в журнал как визуальная проверка.

Договор с командой снимка проверяемый: последняя непустая строка stdout - путь к файлу. Не файл,
пустой файл, нет строки - «не выполнено». Угловые скобки в значении профиля за команду не
принимаются: это «не спрошено», и этап обязан спросить, а не запустить их в оболочке.

## Профиль проекта

`.volna/project.md`, секция `## Профиль`. Правило: **чего в профиле нет, того этап не делает** — молча, без
записи «пропущено». Значение в угловых скобках (`<chrome-devtools|нет>`) значит «не спрошено»: этап
останавливается и спрашивает, а не догадывается (`state.ts:isPlaceholder`).
