# Волна для pi

Упрощённая «Волна» для [pi](https://pi.dev): ведение одной задачи по флоу этапов с журналом работ,
адвокатом дьявола в отдельном процессе и опциональной визуальной проверкой в браузере.

Что делает пакет:

- **флоу из десяти этапов** — от приёма задания до доставки в git и закрытия задачи;
- **журнал работ**, по которому задача восстанавливается с нуля в новой сессии;
- **адвокат дьявола** отдельным процессом `pi` с чистым контекстом и правами только на чтение;
- **визуальная проверка** веб-выхода в браузере pi-chrome-devtools: ошибки консоли, ответы 4xx/5xx, скриншот;
- **доставку в git**: ветка задачи, коммит на каждую часть, push с согласия человека;
- **гейт на правки** до этапа реализации и **отмену сжатия контекста**, пока журнал отстаёт.

Чего в пакете нет: трекера задач, PR, вики и базы знаний. Профиль проекта эти строки уже описывает,
этапы про них знают, но кода под них пока нет. Доставка работает только в git: другие системы контроля
версий «Волна» читает, но не пишет.

## Установка

```bash
pi install git:github.com/alex-venediktov/Volna-Pi
```

Для проекта, а не глобально:

```bash
pi install -l git:github.com/alex-venediktov/Volna-Pi
```

Локальная разработка пакета — без установки:

```bash
pi -e D:/Projects/AI/Volna-Pi
```

Дальше в рабочем репозитории:

```
/volna:init                       развернуть .volna (профиль проекта, каталоги журнала, .gitignore)
/volna:doctor                     проверить настройку
/volna:task <задание или ссылка>  принять задание и начать флоу
```

## Этапы

| # | Этап | Уровень | О чём |
|---|---|---|---|
| 1 | `intake` | required | принять задание текстом или ссылкой на файл, карточка, журнал |
| 2 | `analyze` | expected | разбор задания по коду, похожие места, вопросы |
| 3 | `spec` | expected | постановка своими словами, критерии приёмки |
| 4 | `plan` | expected | план правок по файлам, порядок, риски |
| 5 | `implement` | expected | итерация правок по плану |
| 6 | `advocate` | expected | адвокат дьявола по полному диффу |
| 7 | `unit-tests` | expected | тесты по конвенциям проекта |
| 8 | `visual` | optional | браузер, ошибки консоли, скриншот |
| 9 | `deliver` | expected | git: ветка задачи, коммит части, push |
| 10 | `close` | required | итог и часы в журнал: части либо всей задачи |

`implement` → `advocate` крутится до вердикта «чисто». Любая доработка кода — новая итерация
`implement`, и адвокат после неё обязателен снова.

Уровни: **required** — нужно решение человека; **expected** — делаем по умолчанию, пропуск с
причиной в журнал; **optional** — по ситуации.

## Команды

| Команда | Что делает |
|---|---|
| `/volna:init` | развернуть `.volna` в текущем репозитории |
| `/volna:task <задание>` | принять задание: текст или ссылка на файл; без аргумента — следующая часть |
| `/volna:analyze` … `/volna:close` | войти в этап или открыть его новую итерацию |
| `/volna:skip <этап> <причина>` | пропустить этап, причина уходит в журнал |
| `/volna:status` | этап, прогресс, открытые вопросы, замечания к журналу |
| `/volna:journal [что]` | дописать журнал по текущему этапу |
| `/volna:checkpoint` | привести журнал к восстановимому состоянию |
| `/volna:baseline` | снять снимок дерева (проект без системы контроля версий) |
| `/volna:doctor` | проверить настройку: профиль, состояние, источник изменений, браузер |
| `/volna:off`, `/volna:on` | заглушить и вернуть шапку и подсказки |

### Задание ссылкой на файл

Постановка часто уже лежит файлом. `/volna:task` и `volna_task` берут её и по ссылке: путь от корня
проекта или от текущего каталога, абсолютный путь, путь в кавычках, `@docs/task.md`, `file://`-адрес,
`~/задание.md`. Путь в аргументе команды дополняется по Tab. В журнал уходит текст файла дословно, в
`source` - его путь.

Ссылка, которая не открылась, - ошибка, а не текст задания: файла нет, ссылка ведёт на каталог, файл
пуст, в нём двоичные данные, формат не текстовый (`.docx`, `.pdf`) или он крупнее 128 КБ. Иначе в
журнал вместо постановки попало бы имя несуществующего файла. Текст с упоминанием файла остаётся
текстом: ссылкой считается только то, в чём нет пробелов, либо то, что нашлось на диске.

## Задача из нескольких частей

Работа не помещается в один заход — задача **остаётся одной**: один журнал, одна ветка, один
идентификатор. Части — её внутреннее деление: цикл `spec → plan → implement ⇄ advocate → unit-tests →
visual → close` проходится по разу на каждую, между частями стоит `/clear`.

Список частей живёт в подпункте `**части:**` секции «Состояние» — там же, где всё, что нужно для
продолжения:

```
**части:**
1. схема хранения - сделано (2026-08-16, 3ч)
2. приём шага по форме - в работе
3. продолжение цепочки - не начата
```

Пишется он инструментом (`volna_journal action=state`, поле `parts`), номера `part`/`parts` во
frontmatter считает код по списку. Список **переносится сам**, когда «Состояние» переписывают без
него: он источник правды об остатке, и забытое в одном вызове поле стёрло бы остаток задачи.

| Что | Как |
|---|---|
| предложить деление | этап `spec`, вариантами; решает человек |
| закрыть часть | `volna_finish` с `part=true`: итог и часы части в журнал, задача остаётся активной |
| продолжить после `/clear` | `/volna:task` **без аргумента** — поднимает задачу и входит в `spec` следующей части |
| закрыть задачу | `volna_finish` без `part`: суммарные часы, активная задача снимается |
| бросить работу | то же полное закрытие, остаток обязателен в `left` — незакрытые части помечаются «снята» |

Шапка, футер и `/volna:status` показывают текущую часть и остаток.

## Инструменты

Модель ведёт флоу инструментами, а не текстом: этап, номер итерации, метку времени и формат секции
ставит код.

| Инструмент | Назначение |
|---|---|
| `volna_init` | развернуть `.volna` (модель может сделать это сама) |
| `volna_task` | принять задание, создать журнал |
| `volna_stage` | перейти на этап, открыть новую итерацию, пропустить этап |
| `volna_journal` | секция этапа в лог, «Состояние», открытые вопросы, проверка восстановимости |
| `volna_advocate` | адвокат дьявола отдельным процессом |
| `volna_visual` | браузерная проверка через CDP: консоль, исключения, сеть, скриншот |
| `volna_deliver` | доставка в git: ветка задачи, коммит части, push |
| `volna_recall` | поиск по прошлым журналам и знаниям |
| `volna_finish` | закрыть часть (`part=true`) или задачу: итог, часы, снятие активной |

## Доставка в git

Этап `deliver` стоит перед `close`, то есть **внутри цикла части**: одна ветка на задачу, коммит (и не
один, если часть того требует) на каждую часть. Что именно делает этап, решает профиль:

| Строка профиля | Значение |
|---|---|
| `доставка` | `нет` (этапа не существует), `commit`, `commit+push` |
| `ветка` | шаблон имени: `<тип>` (bugfix/feature/research), `<задача>`, `<слаг>`; `нет` — работать в текущей |
| `база` | от чего ответвляться; пусто — от текущей ветки |
| `удалённый` | имя удалённого для push; пусто — `origin` |

Инструмент `volna_deliver`:

| Действие | Что делает |
|---|---|
| `status` | ветка, незакоммиченные файлы, upstream, сколько коммитов не отправлено, текущая часть |
| `branch` | создаёт ветку задачи по шаблону и записывает её в журнал; повторный вызов ничего не ломает |
| `commit` | коммит с сообщением по конвенции проекта, запись в лог (хэш, файлы) |
| `push` | отправка ветки; ставит upstream первым push-ем |

**Push — единственное действие флоу, которое видно снаружи**, поэтому он спрашивает подтверждение
диалогом там, где есть UI, и требует явного `confirmed` там, где UI нет. Без согласия человека push не
делается. Force push флоу не делает никогда: отклонённый push — повод разбираться, а не давить.

Проверки, которые держат «коммит на часть» честным:

- предупреждение о коммите без записи в журнале считает записи **текущей части**, а не всей задачи;
- адвокат сравнивает с `HEAD`: закоммитили часть — база сдвинулась сама, не закоммитили — адвокат
  увидит обе части, и это правда, а не сбой;
- в проекте без системы контроля версий закрытие части **пере-снимает снимок дерева**: это и есть
  аналог коммита;
- закрытие задачи предупреждает, если остались незакоммиченные правки или неотправленные коммиты.

## Откуда берутся изменения

Адвокат проверяет **сделанные правки**, а не весь проект, поэтому ему нужен список изменённых файлов и
дифф. Источник определяется сам:

| Признак в проекте | Источник |
|---|---|
| строка профиля `изменения: <команда>` | своя команда проекта — TFVC (`tf vc status`), Perforce (`p4 opened`), скрипт |
| каталог `.git` | `git diff` против базы (по умолчанию `HEAD`) плюс файлы вне индекса |
| каталог `.svn` | `svn status` и `svn diff` |
| каталог `.hg` | `hg status` и `hg diff` |
| ничего из этого | **снимок дерева**, который «Волна» снимает сама |

Снимок снимается автоматически при входе в `implement` (и командой `/volna:baseline`): хэши файлов плюс
копии текстовых, в `.volna/baseline/<задача>/`. Дифф против него строится своим unified diff, поэтому
адвокат в проекте вообще без системы контроля версий работает так же, как в git.

Что источник не покрывает, он говорит прямо: `svn diff` не показывает неверсионированные файлы, команда без
`дифф` отдаёт файлы целиком, снимок не различает переименование от «удалил и добавил». Эти примечания
уходят и адвокату, и в ответ инструмента — проверка не делает вид, что видела больше, чем видела.

Строки профиля: `изменения` (список файлов), `дифф` (необязательно), `не смотреть` (что снимок пропускает
помимо `node_modules`, `dist`, `bin`, `obj`, `.vs` и прочих очевидных).

## Журнал

```
.volna/
  state.json                       указатель активной задачи            (не коммитится)
  project.md                       профиль проекта                      (коммитится)
  journal/TASK-<id>.md             frontmatter + «Состояние»            (не коммитится)
  journal/logs/TASK-<id>.log.md    append-only лог итераций             (не коммитится)
  visual/                          скриншоты браузерных проверок        (не коммитится)
  advocate/                        изменения, отданные адвокату         (не коммитится)
  baseline/<задача>/               снимок дерева без системы версий     (не коммитится)
```

Файл состояния размером с экран — его читают целиком при возврате к задаче. Лог крупный и
читается адресно. При противоречии слоёв прав файл состояния.

Формат: скилл `volna-journal`. Флоу и обязанности этапов: скилл `volna-flow`.

## Адвокат дьявола

`volna_advocate` пишет изменения в файл, запускает

```
pi --mode json -p --no-session --no-extensions --no-skills --tools read,grep,find,ls,bash \
   --append-system-prompt <промпт адвоката>
```

и передаёт ему критерии приёмки из журнала. Отчёт заканчивается строкой
`ВЕРДИКТ: чисто | дефекты | нужен человек`, по ней флоу решает, идти дальше или открывать новую
итерацию.

Дифф в контекст родительской сессии не попадает: за него уже заплатили при правках.

Модель адвоката — строка профиля `модель адвоката` (`наследовать` или id модели). Отдельный процесс
позволяет проверять дешёвой моделью, а работать дорогой, или наоборот.

Адвокат вернулся пустым — дело в запуске подпроцесса, а не в коде: модель недоступна, нет ключа
либо провайдер приходит из расширения pi, а расширения у адвоката отключены. Последний случай
лечится строкой профиля `расширения адвоката: да`.

## Визуальная проверка

Опциональный этап. Проверка идёт в том браузере, которым управляет расширение
[pi-chrome-devtools](https://www.npmjs.com/package/@narumitw/pi-chrome-devtools):

```bash
pi install npm:@narumitw/pi-chrome-devtools
```

Своего движка браузера «Волна» не поднимает — два браузера в одном проекте дают две разные картинки
и спор о том, какая правда. `volna_visual` берёт endpoint из `~/.pi/agent/pi-chrome-devtools.json`
(по умолчанию `http://127.0.0.1:9222`), переменных `PI_CHROME_DEVTOOLS_HOST`/`PORT` или строки
профиля `endpoint браузера`, подключается по Chrome DevTools Protocol и собирает:

| Что | Влияние на вердикт |
|---|---|
| ошибки консоли (`console.error`, `assert`) | красный |
| необработанные исключения страницы | красный |
| ответы 4xx/5xx и упавшие запросы | красный |
| предупреждения консоли | не влияют, но показываются |
| скриншот PNG в `.volna/visual/` | человеку; модели — если профиль разрешил |

Браузер не запущен — инструмент так и говорит: поднять его вызовом `chrome_devtools_navigate`
(расширение запускает браузер само) и повторить `volna_visual`. Свой браузер «Волна» не гасит и не
перезапускает.

Шаги до нужного состояния передаются в `steps`: `goto`, `click`, `fill`, `press`, `waitfor`, `wait`,
`scroll`. Проверка открывает новую вкладку и закрывает её за собой; `reuse_page: true` работает в
уже открытой вкладке, когда состояние набрано руками (вход в систему, заполненная форма).

## Профиль проекта

`.volna/project.md`, секция `## Профиль`. Правило: **чего в профиле нет, того этап не делает**.
Значение в угловых скобках означает «не спрошено» — этап остановится и спросит, а не догадается.

| Строка | Смысл |
|---|---|
| `тесты`, `сборка`, `запуск` | команды проекта |
| `визуальная проверка` | `chrome-devtools` или `нет` |
| `скриншот модели` | отдавать ли картинку модели |
| `endpoint браузера` | адрес CDP, если браузер слушает не то, что настроено в pi-chrome-devtools |
| `эталон` | путь к эталонной реализации, если работа — порт |
| `модель адвоката` | `наследовать` или id модели |
| `расширения адвоката` | `да`, если провайдер модели регистрируется расширением pi |
| `гейт правок` | `да` не даёт править код до этапа реализации |
| `доставка`, `ветка`, `база`, `удалённый` | этап `deliver`: что делаем, как зовём ветку, откуда и куда |
| `изменения`, `дифф` | команды, дающие изменённые файлы и дифф, если VCS не git/svn/hg |
| `не смотреть` | что снимок дерева пропускает, через запятую |
| `трекер`, `вики`, `kb` | оставлено на будущее, сейчас `нет` |

## Разработка

```bash
npm install          # typescript и типы pi
npm run check        # проверка типов
npm test             # тесты: журнал, флоу, гейты, дифф адвоката
pi -e .              # запустить pi с этим пакетом без установки
```

Тесты идут обычным node с раздеванием типов и модели не касаются: проверяется то, что должно
работать одинаково при любой модели. Живую загрузку в pi удобно смотреть через RPC:

```bash
printf '%s
' '{"id":"1","type":"get_commands"}' | pi --mode rpc --no-session -e .
```

### Промпты и токены

Всё, что уходит модели — описания инструментов, блок обязанностей, инструкции этапов, промпт адвоката —
написано **по-английски и сжато**: пакет рассчитан на локальные модели, где каждый токен префикса платится
на каждом запросе. Русский остаётся там, где его читают люди: журнал, сообщения команд, подсказки в футере,
профиль проекта и этот файл. Строка в блоке обязанностей велит модели отвечать человеку и писать журнал
по-русски.

Замер на Qwen-подобном токенизаторе (llama.cpp `/tokenize`): постоянные накладные — 1268 токенов на запрос
(описания инструментов) плюс 137 на описания скиллов; вход в этап — 790–860 токенов; вызов адвоката — 598.
Перевод и сжатие сняли около 31% от прежних значений.

Расширение загружается через jiti, сборки не требует. Ядро (`extensions/volna/*.ts`) не зависит от
API pi нигде, кроме `tools.ts`, `commands.ts` и `index.ts` — журнал, флоу и поиск можно прогонять
обычным node:

```bash
node --experimental-strip-types your-script.ts
```
